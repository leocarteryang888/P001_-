# 过滤器选型子模块

## 职责

本模块只根据以下输入生成标准过滤器规格和数量：

- 过滤器安装形式：抽拉过滤或框架过滤；
- 过滤器类型；
- 箱体宽度模数；
- 箱体高度模数。

过滤段长、检修段长和检修门不属于本模块职责。

## 文件边界

| 文件 | 职责 |
|---|---|
| `index.html` | 页面结构与语义 |
| `css/filter-selector.css` | 页面样式 |
| `data/filter-database.js` | 过滤器类型和 6–33M 标准排布数据 |
| `js/filter-selector.js` | 选型计算和结果渲染 |

本模块物理位置为 `src/01-过滤器选型/`，是 P001 Git 仓库内唯一过滤器选型源码。整机工作台通过相对路径进入本模块，但不复制其业务数据或计算逻辑。

## 规格编码

规格编码由宽、高方向的单个排布值拼接而成。例如宽度值 `5`、高度值 `4` 对应规格 `54`。同一规格会合并统计数量。

## 维护规则

1. 默认标准排布变化只修改 `data/filter-database.js`；浏览器覆盖数据可通过“数据库管理 · Excel”导入。
2. 计算与展示变化只修改 `js/filter-selector.js` 或 CSS/HTML。
3. 数据库不得加入过滤段长或检修门字段。
4. 修改后必须验证两种安装形式的全部 6–33M 宽高组合。

## Excel 数据库管理

页面右上角“数据库管理 · Excel”提供在线查看、导出和导入窗口：

- 点击“在线查看数据库”，可直接浏览当前生效的过滤器类型、宽度排布和高度排布，不会下载文件。

1. 导出当前数据库为 XLSX 模板，工作表为“过滤器类型”“宽度排布”“高度排布”。
2. 在 Excel 中保留表头、编辑数据；两张排布表都必须完整包含 6–33M，每个组合用加号分隔（例如 5+5），元素仅限 3–6。
3. 导入 XLSX 或 XLS（最大 2MB），校验通过后点击“应用导入”。不接受公式、重复模数、重复类型标识或缺失排布。
4. 数据仅保存在当前浏览器的 localStorage，不会覆盖磁盘上的默认数据库。更换浏览器、清除缓存或改变页面地址后可能需要重新导入；请保留导出的 Excel 备份。
5. 导入替换全部三张表，不进行部分合并；校验失败不改变当前数据库。导出始终读取当前生效数据。

新增职责文件：`js/filter-data-io.js`（格式转换与校验）、`js/database-dialog.js`（窗口和存储流程）、`css/database-dialog.css`（窗口样式）。

Excel 读写采用本地 SheetJS CE 0.20.3，不依赖运行时网络。来源：https://cdn.sheetjs.com/xlsx-0.20.3/package/dist/xlsx.full.min.js ，许可证见 `vendor/LICENSE-SheetJS`。

验证命令（在本模块目录执行）：

```powershell
node tests/filter-selector.test.js
node tests/filter-data-io.test.js
```

## 整机工作台专业选型回传

2026-10-07：当前唯一最终ThreeJS工作台已通过原型适配层接入本模块。标准排布规则仍仅由本目录维护；工程师从最终页选中对应段、保存真实截面、启动专业选型，再明确应用结果。本模块原有协议和算法未改；最终页自行校验并CAS保存原型项目，不写旧V2项目。结果记录规格/数量及规则来源，不能据此认定效率、阻力已计算。

工作台通过同源 `/src/01-过滤器选型/index.html` 打开本模块，并带入稳定 `projectId / unitId / segmentId`、机组宽高及输入指纹。模块按当前生效的过滤器类型和抽拉/框架排布数据库计算；宽高须为 6–33M 内、可整除 100 mm 的标准模数。类型及过滤形式由工程师确认。结果包含规则版本、数据库内容指纹、输入快照、排布明细与性能复核警告；仅点击“应用到工作台”才回传。效率、初阻力、终阻力仍需按过滤器产品资料确认。

本地服务下采用同源消息及 nonce 隔离的结果暂存。工作台再次校验目标 ID、机组条件指纹和过滤尺寸，之后才写入功能段 `interface.calculation / selection / output / validation`；规则结果保存为 L2，人工输入仍为 L1。`file://` 不支持此回传流程。
