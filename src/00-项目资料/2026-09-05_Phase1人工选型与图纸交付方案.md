# Phase 1 人工选型与图纸交付修改方案

编制：agent1（GPT-6 Astra，高；暖通组合式空调机组选型技术专家）  
评审：agent2（GPT-5.6 Sol，中；日常手工计算的选型技术支持）  
日期：2026-09-05；状态：agent2第二轮评审通过，已进入分任务实施。

## 1. 本轮明确的产品边界

以本次用户指令为第一阶段最高业务依据：**普通技术支持先手工完成性能选型，在软件中录入结果、编排真实功能段、核对结构和资料，再输出可编辑 CAD 图与对应 PDF 方案图。** 不执行空气处理、盘管换热、过滤器性能、风机曲线、段阻力或负荷计算，不以算法缺位阻止人工方案交付。几何尺寸汇总、字段完整性、取值合法性和变更复核属于资料校核，允许执行。

本方案为 V1.5 总体规格的 Phase 1 修订依据；长期算法路线保留，但不得阻碍本轮交付。修改主规格、项目入口、架构规则及维护 Skill 时同步声明此优先级。既有 01/02 专业模块保留独立访问，工作台不依赖其算法返回完成状态。

## 4. 技术支持的可执行流程

1. 建项目，填写客户、项目号、技术支持及项目工况，允许保存草稿。
2. 建机组，填写编号、数量、安装型式、送风量/新风比/机外余压、箱体宽高。截面仅为人工确定的外形尺寸，本轮移除硬编码候选推荐和迎面风速计算；手工输入尺寸替代原候选入口。
3. 根据手工方案添加和排序功能段；段序与气流方向一致，停用段不参加图纸。提供点击添加、前移/后移，不能只靠拖拽。
4. 逐段填写人工选定产品和性能结果，结构及接口数据；来源可填厂家软件报告、手算记录、样本版本等，不要求上传文件。每段点击“确认本段录入”，记录确认人、时间和段资料快照；段资料变化即失效。
5. 检查资料：缺失项能定位到机组字段或相应段；区分“缺项/无效值”“需要工程师确认的顺序或性能匹配提醒”。不推算并填充性能。
6. 工程师填写姓名并确认“已人工核对性能、段序、接口及尺寸”。只有当前资料完整、结构可绘且确认与当前快照一致时，允许正式DXF/PDF输出。
7. 同一资料快照生成CAD与PDF，文件名含项目号、机组号、修订号；修改资料后必须重新确认，原已生成文件不被后台改写。

保存草稿和JSON备份不受专业缺项影响；格式损坏、未知版本仍拒绝导入。旧数据补齐新增容器但不制造已复核状态，不丢弃原七段式字段。

成果区列出本项目每台机组完成度；本轮按钮明确为“导出当前机组”。只校核当前导出机组，其他未完成机组不阻断其出图。切换机组后对应确认和完成度独立。每段共用数量字段（正整数，结构段默认1）及人工备注。状态转移：草稿→资料齐全待确认→逐段确认齐全→整机已复核可出图；任何图纸相关编辑→整机待复核，相关段确认一并失效。机组公共工况/截面改变时全段确认失效。

## 5. 数据与字段契约

保持 `schemaVersion:2` 与已有七段式接口兼容。新增独立 `manual-selection.js` 维护类型字段、完整性与复核快照；项目模型只做稳定归一化/初始化。`calculation`不运行也不填虚构数据。`selection`保存人工型号与来源，`output.manual`保存结果，`drawing`保存实际结构。新增字段全部进入JSON保存、读取、复制和迁移。

### 5.1 机组资料

正式出图必填：项目名称/编号、机组编号、数量（正整数）、技术支持、人工机组型号或方案名称、修订号、人工复核人；送风量>0、机外余压≥0、外形W/H>0、面板厚度>0、安装型式、气流方向、检修侧。宽/高/长限制可留空，填写则必须大于0且不得被实际尺寸超过。

机组出图设置：方案名称、修订号、图号、图纸备注、气流方向、检修侧、底座高度（可为0）。总长为启用段长和，立式图按段高叠加且明确整体外形轴；最终W/H/L含义不得与图形冲突。保存总风量、总机外余压仅引用唯一现有机组输入，避免profile与designConditions显示陈旧的重复值。

**坐标与尺寸的唯一约定**：机组物理坐标X为纵向长度、Y为宽度、Z为竖向高度。已有cabinetWidth表示垂直于气流截面宽A；已有cabinetHeight表示垂直于气流截面另一尺寸B。卧式界面称“箱体宽W、箱体高H（不含底座）”，气流轴X，功能段length沿X，实体外形L=Σlength，W=A，H=B+底座。立式界面必须改称“截面宽W、截面深L”，气流轴Z，功能段length显示“段高”，外形L=B，W=A，H=Σlength+底座；额外记录“气流轴总段长Σlength”不得混称整体L。下进上出从底座顶面顺序向上，上进下出从最高段顺序向下。侧视投影X/Z、俯视X/Y、端视Y/Z，正向箭头依真实气流轴绘制，接口坐标依段局部X/Y/Z映射。安装限宽比较W、限高比较H、限长比较L；不能继续用截面B直接判立式整高。

数值验例：A=1200、B=1000，启用段气流轴尺寸为500/800/600，底座100。卧式外形W×H×L=1200×1100×1900mm；立式外形W×H×L=1200×2000×1000mm；两者气流轴总段长都是1900mm。立式三视图侧视1000×2000、俯视1000×1200、端视1200×2000；任何投影不能仍画成1900mm水平段链而叫立式。

### 5.2 功能段人工结果

| 段类 | 正式出图必填人工结果 | 条件/补充字段 |
|---|---|---|
| 新风、回风、混风、送风、排风 | 结构说明、选型来源 | 风口名称、所在面、宽高、中心位置；有阀时录阀规格 |
| 初/中/高效过滤 | 型号、效率等级及标准文字、数量、单件宽高深、设计风量、初阻力/终阻力 | 安装/抽出方向 |
| 冷水/热水盘管 | 型号、能力kW、风侧阻力Pa、水流量m³/h、水阻力kPa、进/出水温度、排数、接管规格 | 冷水盘管补凝水接口；不自动算换热 |
| 电加热 | 型号、热量kW、电源、级数/控制方式 | 接线侧；安全联锁只作为人工说明 |
| 加湿 | 型号、方式、加湿量kg/h、风侧阻力、介质接口规格 | 电功率、排水接口、吸收距离说明 |
| 送/回/排风机 | 型号、数量、选定风量、选定全压、电机功率、电源、调速方式 | 选型工况/厂家报告编号；不由余压加阻力推风机压力 |
| 消声 | 型号/构造规格、长度、风侧阻力、消声性能说明 | 不强迫虚构单一dB数值 |
| 检修/空段/均流/挡水 | 构造说明和来源 | 不要求型号、能力与阻力，型号可选 |
| 热回收 | 型号、形式、送/排风量、双方阻力、效率类型和值 | 允许记录；双气路尚未建模时阻断正式图纸 |

所有启用段共用：名称、段长/气流轴尺寸>0、结构说明、检修门（有/无）及有门时的侧向/宽高/沿段位置；需要风口或水/凝水口时以显式接口行保存名称、形状、规格/尺寸、所在面和中心位置。无接口的段明确选择“不需要接口”，避免空白误判。坐标必须落在相应表面范围，端部风口尺寸不能大于外形。未知导入类型保留数据并列为需处理，不能默认为完成。

结构字段按类型有合理默认显示，但默认段长500或空型号不是人工确认值；按字段完整性和工程师最终确认双重把关。数值校核区分空字符串与0，所有性能有限数值，流量/能力/功率>0，阻力可为0，效率范围按类型进行合法性校核。

## 6. 简洁专业界面

保留现有项目中心和两步创建。配置工作台以白/浅灰为主、深蓝标题与青色选中态。顶栏显示当前项目/机组、保存草稿、资料检查、人工复核、DXF、PDF。状态明确为“人工选型录入·不执行功能段性能计算”。

工作台四个业务页签：**机组资料 / 功能段配置 / 检查与复核 / 图纸预览**。功能段配置左侧段库/有序段清单，中间比例图和当前段表单；选中段表单分“人工结果、结构接口、来源说明”三组，不展示Input/Calculation/BOM空页签。窄屏顺序排布并可滚动，1366×768下工具按钮和当前表单可达，1920×1080下图形与表单可同屏。工程数值均有单位，必填有标识，不用“0候选”空表占据大块页面。

持续状态显示已录入段数/启用段数、实际外形、缺项数、复核状态；缺项按钮定位并聚焦字段。模型或项目修改后实时变成待复核；点击复核不运行性能计算。现有专业子模块链接归入辅助工具并注明外部/独立选型后回填。

## 7. 图纸交付规则

增加纯几何模块 `drawing-model.js`，其同一图元清单（线、多段线、文字、圆）同时驱动SVG预览、DXF、PDF。几何以mm建立，DXF模型空间1:1且声明毫米；PDF按标准A3横向页面缩放并标比例，极端长机组使用分页/分图而非不可读缩小。项目文字转义；中文在DXF用Unicode转义并设常见中文字形样式，PDF需要中文正常显示。

CAD明确采用**可编辑二维DXF**，不能把SVG改后缀为DWG。PDF必须真实下载`.pdf`文件，不能仅提供浏览器“打印自己另存”；可使用本地浏览器PDF库和字体，所有必需文件随03模块保存并记录许可证。

第一页为侧视、俯视、端视、气流箭头、段序/名称、单段尺寸和外形尺寸、检修门与已录入接口、项目/机组/图号/修订/日期/复核人标题栏。第二页或续页列人工录入选型参数与结构接口表；多段时分页、重复表头，不截断文字。DXF须包含对应信息（图元及表格文字），两种格式使用同一标题/资料修订/图纸快照。方案图固定标注“人工选型结果及外形方案图；尺寸单位mm；性能由录入人与复核人确认”，不称生产加工图。

## 8. 小任务与验收

agent1负责拆分，所有实现由 GPT-5.6 Luna 执行；每项完成交agent2独立验收，不通过则由agent1重新划分整改。

| 任务 | 唯一写入责任 | 可交付与验收 |
|---|---|---|
| T1 人工数据与完整性 | `manual-selection.js`、`project-model.js`兼容扩展、对应测试 | 类型表/新增常用段；必填/0/负数/接口越界；旧数据不丢；草稿可保存；快照失效；多机组互不污染 |
| T2 图形与真实导出 | `drawing-model.js`、`drawing-export.js`、必要vendor及测试 | 同源三视图；DXF可由独立解析器读取；PDF真实文件、中文、分页；尺寸与接口一致；不支持型式阻断 |
| T3 业务界面整合 | `app.js`、`index.html`、新增样式 | 人工表单/资料检查定位/复核/下载完整流程；无假计算/候选；键盘操作/1366×768验证；支持旧入口/JSON |
| T4 文档与交付整改 | 主规格、入口、架构/README及Skill同步 | 对齐人工Phase1、操作路径、图纸边界；按独立验收缺陷回归修复 |

最终独立场景：新建项目→机组→按人工示例填全→保存/JSON往返→复核→DXF与PDF下载；故意缺能力/尺寸、负数、接口越界、修改已复核段、停用段、旧项目导入、多个机组切换、超长段/多段分页均验证。根任务负责基线与最终整体验证，agent2对每项出具通过或带具体复现步骤的不通过结论。任何相关测试或图纸验图失败均不得宣称完成。

AC映射：AC-01对应第4节草稿；AC-02对应第5节结构化字段；AC-03/04对应第4节逐段确认及快照失效；AC-05对应第4/5节出图门槛；AC-06/07对应第7节同源真实成果；AC-08对应第4节单机出图/全项目状态；AC-09对应第6节界面；AC-10对应第1/8节范围与文档同步。本轮不提供项目批量图纸导出，因此没有静默跳过未完成机组的行为。

## 9. 评审记录

首轮不通过：R1缺逐段确认、R2原候选可能仍暗示计算能力、R3单机/全项目门槛未明确、R4立式几何语义含糊。已分别在第4节补确认状态/失效与单机门槛，第4节取消推荐候选，第5.1节给出坐标及数值例。

第二轮结论：agent2确认R1-R4闭环，通过进入T1-T4实施。双气路热回收暂缓出图可接受，但必须在创建选项前置提示、检查清单说明原因且DXF/PDF硬阻断。实施成果仍逐项独立验收，通过方案不等于代码或图纸已交付。
