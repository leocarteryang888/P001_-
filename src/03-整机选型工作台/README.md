接入须在HTTP本机服务下使用。首次进入旧浏览器草稿需显式保存/发布；后续需先保存输入再启动。旧V2仍只读，其导入副本只保留输入，不导入旧专业计算结果。盘管目前仍为独立入口，3D共享库统一读取尚未接入，本轮未宣称完成这两条链路。

### 当前最终 ThreeJS 工作台：参数化外形与人工门/接口定位（2026-10-09）

图纸预览及 SVG 视图、PDF、DXF 均由同一绘图几何模型生成。外形依据已确认的箱体宽、高和功能段长度；门与接口位置须在对应功能段中明确录入所在面、偏移及开口宽高，不会把旧门/接口字段或示意值当作定位数据。截面未确认、尺寸/段长缺失，或门/接口定位缺项、无效、越界时，会显示诊断并阻止 PDF/DXF 导出。

该能力是参数化外形及接口布置图，不是制造级 3D CAD。当前 Three.js 预览中的内部构件和法兰厚度仍有示意占位，不能作为工程精确几何或从属尺寸依据；系统也没有收到外部制造模型。绘图逻辑位于 `js/prototype-drawing.js`，门/接口输入位于 `js/prototype-cad-inputs.js`，相关测试位于 `tests/prototype-drawing.test.js`。现阶段不覆盖制造级板厚、框架/法兰型材、拼接节点、门铰链与锁扣、接管实体/连接细节、检修空间及内部零件制造几何；DXF 不是原生 DWG，PDF 为 A3 栅格图纸。

推进真实制造 CAD 前，需提供经确认的箱体板厚与板材/保温结构、框架和法兰截面/连接规则、段间拼接与底座结构、门及检修要求、各类接口的规格/方向/标高和连接细节，以及对应设备的已批准制造图或 CAD/STEP 模型作为依据；当前未收到外部模型。生成结果仍须由工程人员校核后用于制造。

新增维护文件：`js/prototype-selection-handoff.js`、`js/prototype-selection-ui.js`、`tests/prototype-selection-handoff.test.js`。浏览器验收使用独立8877端口及临时快照，不修改8765实际用户数据。

### 旧 V2 专业接口资产（保留复用，不是第二个运行入口）

过滤段和表冷段的规则原则、适用范围、来源、结果状态与警告显示在对应功能段详情内。过滤器规则只查当前生效的排布数据库，箱体宽高需处于 6–33M 且能整除 100 mm；初效段仅允许 G2/G3，中效段仅允许 F300/F500，高效段仅允许 H；G+F 复合型和活性炭类型因单段适用范围未定义而禁止单段回写。过滤效率和阻力需另按产品资料确认。盘管规则只查 25W 标准表，不计算热工性能；型号为几何参考，非 25W、缺少记录、管径不符及规范尺寸冲突均不回写。加热盘管不复用表冷器模块，当前明确标记为 L1 人工选型、待加热盘管专用规则和标准资料确认。风机、加湿、热回收等尚未完成规则与性能数据库的功能继续采用 L1 人工选型，界面不会显示自动推荐结果。

工作台为同源 `/src/01-过滤器选型/index.html`、`/src/02-盘管选型/index.html` 传入稳定项目、机组、功能段 ID 和机组输入指纹。模块明确由用户点击“应用到工作台”后回传。结果通过同源 `postMessage` 及 nonce 结果暂存恢复；工作台再次校验目标 ID、输入指纹、结果规则类型和专业功能段类型。过滤器排布的宽高组合、过滤器类型、规格数量关系及当前生效数据库指纹也会逐项复核；数据库缺失、已变化或消息快照不完整时拒收。幂等 ACK 阻止重复写入。应用时同时更新项目主保存和项目索引；每个项目带递增修订号，普通保存与专业回写都先比对持久化修订号，其他标签已保存新版本时拒绝旧快照并提示刷新。存储失败回滚，结果只写目标项目，不覆盖零件库或已打开的其他项目。保存按钮仅绑定一个保存入口。刷新工作台后可恢复目标机组并重放未处理结果。该协议依赖同源本机服务，`file://` 模式不可回传。

通过结果分别存于功能段七段式接口 `calculation.professionalRule`、`selection.professionalResult`、`output.automatedSelection` 和 `validation`，包括规则 ID/版本、数据库内容指纹、来源、选型时间、输入快照、输出数据和警告。活动机组的扁平编辑数组与机组段数组在规范化、刷新和保存时保持同步，避免序列化旧段数据。人工改写型号会清除自动结果并标成 L1；再次运行专业模块产生 L2。项目审计记录同样保留规则与来源信息。

### WK 无框架式箱体截面候选接入（2026-10-08）

机组资料页的截面入口消费盘管模块 `CoilSelector.listFaceSectionCandidates()`，候选库来自 `src/02-盘管选型/data/coil-section-database.js`。工作台不复制源表，也不实现盘管算法。初始风速范围 1.5–3.0 m/s 为可编辑候选筛选条件，不是规范判定；工程师需在 WK 候选中手选并点击“确认截面”。源表推荐标记只展示，不自动推荐。手工非标仅展示名义截面风速几何示值，不代表盘管迎风速度或性能。

机组风量改变时保留已确认箱体宽高，不自动换选；WK 候选速度即时按送风量重算，超出已选筛选范围时显式提示，既有专业结果按现有失效机制置待复核。当前入口确认的是机组实际箱体宽高，非盘管型号或热工性能。项目数据仍通过现有明确保存/CAS 流程写入。

旧演示/草稿机组可能只有 `unit.airflow`（例如 `26000 m³/h`），没有规范的 `designConditions.airVolume`。机组资料及截面候选计算仅在 canonical 字段不存在时，读取带单一明确数值的旧值作为显示/计算输入；不会自动补写或迁移项目。工程师实际编辑送风量后才将值写入 `designConditions.airVolume`。含模糊描述、多值、未填写文本或无效值的旧字符串不解析，界面按未填写处理。

仅有旧箱体宽高不代表截面已确认；截面速度状态只对带明确确认来源的 WK 候选或手工非标截面计算。未确认截面始终提示“截面未确认，暂不计算风速”。

工作台内直接修改箱体宽/高时，旧截面选择保留为失效历史但设置 `confirmed: false` / `status: invalidated`；不会改写新输入尺寸。机组段、结果和示意同步标记待复核，概览与对话框要求重新确认，旧候选不会自动预选。


### 2026-10-09 项目/机组入口与截面确认门槛

项目中心的机组行右键提供“复制机组”“删除机组”；删除需在原位二次确认，删除后出现“退回删除”以恢复最近一次删除。复制为新机组 ID/段 ID，原专业段结果失效，仍须工程师重新选型；以上操作先作用于当前草稿，点击保存后才进入共享快照。项目行可双击或右键“编辑项目信息”，复用现有项目录入表单，保留其机组与既有元数据。

“打开工作台”默认进入机组资料。功能段配置入口要求已明确确认的截面来源及正数宽、高；未满足时保持在机组资料并给出内联提示，不用弹窗、不把遗留宽高当作确认。确认截面后可进入功能段配置，后续段编辑仍按功能段单元进行。
